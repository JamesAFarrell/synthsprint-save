# ADR UK SynthSprint: SAVE Dataset Analysis

## Background

This repository contains analysis code produced as part of [ADR UK SynthSprint](https://dataciseopenlearning.org/synthsprint-a-synthetic-data-exploration/), a four-week data sprint exploring how synthetic data performs across different fidelity levels and real-world use cases.

Our group (Group 2) worked with the [Solent Achieving Value from Efficiency (SAVE) Data, 2017–2018](https://datacatalogue.ukdataservice.ac.uk/studies/study/8676#details), a data collection comprising of survey and electricity consumption data. Our use case focused on **teaching and learning** applications of synthetic data (i.e. the extent to which the data can be used to learn about and practice data science skills).

The sprint tested synthetic datasets at three fidelity levels: Level 1 (structural, metadata-Based), Level 2 (univariate, independent distribution), and Level 3 (multivariate, joint distribution) against the real SAVE data. The results reported contribute to a broader Synthetic Data Utility Framework being developed by ADR UK.

> **Data access notice:** Use of the SAVE data and associated DPUK-created synthetic datasets is subject to the [UK Data Service End User Licence Agreement](https://ukdataservice.ac.uk/app/uploads/cd137-enduserlicence.pdf). Following completion of SynthSprint, all data must be securely deleted in line with those terms. The raw data files are not included in this repository.

## Getting started

### Prerequisites

- R (≥ 4.x)
- [renv](https://rstudio.github.io/renv/) for package management
- [DuckDB](https://duckdb.org/) (installed via R package)
- Access to the SAVE data via the [UK Data Service](https://ukdataservice.ac.uk/) (requires registration and project invitation) and SynthSprint synthetic data provided by ADR UK.

### Setup

1. Clone this repository:
```bash
   git clone https://github.com/JamesAFarrell/synthsprint-save.git
   cd synthsprint-save
```

2. Place data files in the appropriate `data/raw/` subdirectories (see structure above).

3. Run scripts in the `R` folder in order.
